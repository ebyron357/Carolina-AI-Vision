## Outbox processing and error recovery

- Captured leads initially remain `pending_configuration`. An operator explicitly releases them to one approved tenant using `pnpm db:operate release <tenant>` with `DATA_OPERATIONS_APPROVED=true`, `CRM_DELIVERY_APPROVED=true` and protected `OPERATIONS_DATABASE_URL`.
- `pnpm crm:work` processes **one** job. No cron, recurring schedule, public worker endpoint or paid service is activated. Owner must approve a scheduler/worker runtime, frequency and monitoring once the real adapter is verified.
- SQL claims use row locks/SKIP LOCKED, a two-minute lease token and tenant filtering. A 10-second transport deadline aborts slow calls. Expired leases can be recovered; only the current unexpired lease token can finish, preventing stale/replayed completion.
- Transient/timeout failures use persisted exponential backoff (30s to at most one hour), five attempts maximum. Permanent/contract failures dead-letter immediately; exhausted crashed leases dead-letter with audit. Only bounded error categories are stored, never raw remote response bodies or credentials.
- `pnpm db:operate status` returns aggregate queue counts to the operator role, not PII. `pnpm db:operate requeue <lead UUID> <tenant>` explicitly requeues a dead letter and audits the action. Diagnose the underlying failure first. Same stable remote idempotency key is reused. Timeout/dropped-ack cases are at-least-once attempts; only real CRM idempotency prevents duplicate remote effects.
- If acknowledgment persistence fails after remote success, do not invent delivered state or rerun inline. Lease expiry permits recovery with the same remote idempotency key. Local fixtures verify port behavior only, not remote CRM assignment/notification execution.

## Privacy operations

`pnpm db:operate prune <retention-days>` requires explicit approved days (1–3650). It deletes expired abuse-limit rows and old **delivered** local leads/audit/outbox atomically; pending/dead jobs are not silently discarded. `pnpm db:operate erase <lead UUID>` removes a specifically authorized local record, refusing active delivery leases. Stop the worker and wait for expiry before erasure when necessary. Operations audit retains only event/count/time, not the deleted lead reference/payload. Pending/dead record policies need explicit operator review; this is not automatic indefinite-retention approval.

No schedule runs automatically. Owner must approve frequency and retention, including operations-audit retention, backups, exports and external CRM copies. Local erasure does not delete CRM data or backups: complete the CRM/provider deletion procedure separately when that contract exists. Verify requester identity/authority outside the public website; no unauthenticated data-deletion API is exposed.
